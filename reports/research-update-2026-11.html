The wider research programme

Two workstreams, one evaluation pipeline

The research question is whether intrusion detectors generalize beyond the attack procedures and collection conditions they saw during training.

01 / Generate

ConCap

Automates attack execution in controlled container networks. Configurations record the tools, target services and network conditions.

02 / Extract

RustiFlow

Reconstructs flows and computes features from recorded packets or live traffic, with shared measurement logic.

03 / Evaluate

AuthStorm

Packages authentication-attack variants and their provenance for evaluation against existing detectors.

The collection and extraction foundation is in place. Whether existing detectors generalize to these observations remains an empirical question.

Workstream 1 / RustiFlow

A more dependable extraction tool

Recent work focused on capture correctness, reproducible feature semantics and deployment. Performance measurements now distinguish pipeline cost from physical capture capacity.

Capture and flow lifecycle

The pure-Rust reader handles pcap and pcapng without a libpcap dependency. Parser checks reject corrupt timestamps and preserve useful diagnostics.

Adversarial fixes cover TCP termination, expiration and parser edge cases. Reusable features include TCP quality signals and endpoint-aware IP context.

Consistent measurements

Sorted offline exports now match across thread counts. Idle statistics describe observed packet-to-packet gaps, excluding trailing silence.

Validation includes deterministic fixtures and IPv4 / IPv6 realtime checks. The combined offline fixes passed 108 main-crate tests.

One release bundle

Installers, Debian packaging and containers consume the same binary and eBPF bundle. Checksums and a build manifest make the installed version traceable.

The default x86-64-v3 build targets modern CPUs. The installer checks CPU compatibility.

Capture for tap / SPAN use

Promiscuous mode is opt-in. Kernel-managed membership releases automatically when the capture socket closes, including after a forced process exit.

The local veth tests cover membership cleanup. Hardware filtering still needs validation on a physical NIC.

Less work in the userspace path

Changes reduce flow-table lookups, batch packet dispatch and encode CSV rows per shard. A replay benchmark isolates the userspace pipeline.

The CPU-targeted build gave a small, consistent improvement on the full feature set. Stripping reduced the binary from 8.2 MB to 4.5 MB.

Evidence and measurement boundaries

Source: RustiFlow engineering notes, especially 15–22 October and 6 November 2026. The test counts and timings describe the recorded validations, not new runs performed for this report.

Historical veth throughput used a software test setup with offloads and tuning. Application bitrate is not equivalent to classifier packet rate. Physical 40G remains unvalidated; 100–400G is a long-term ambition.

The latest replay median is 12.343 million events/s. It is a userspace measurement with different settings from the earlier eight-thread experiment; it does not establish a speedup. LTO alone had throughput effects within noise; x86-64-v3 improved the full feature set by about 2–3% in that experiment.

Calculations, local evidence and limits

Packet rate = bit rate ÷ (8 × mean packet bytes). At 40 / 100 Gb/s, profile A requires 5.32 / 13.29 Mpps and profile B requires 7.30 / 18.24 Mpps. Multiplying the 12.343 Mpps replay median by each mean yields 92.88 and 67.66 Gb/s. These are arithmetic equivalents, not measured physical throughput.

Exact source L2/FCS accounting was not established. If sizes include complete frames with FCS, adding 20 bytes for preamble and gap reduces the 100 Gb/s estimates to 13.01 and 17.73 Mpps. It does not remove the packet-budget shortfall.

The replay used 20 million generated events, 100,000 stable flows, eight sources, twelve workers, full features and CSV output. Five runs ranged from 11.828 to 12.430 Mpps. NIC reception, kernel/eBPF work and ring reads are excluded. Flow churn, burst load and capture costs can reduce achievable throughput.

The 120-second physical NIC observation averaged only 592 packets/s, with a peak of 6,842 packets in one second. No eBPF ring drops were reported, but this load does not test high-rate capture. The next test should reconcile offered, captured, processed and exported packets under realistic sizes and flow churn.

April was selected for zero reported capture loss; June's direction B had substantial loss. Size-bin shares use available IPv4/IPv6 histogram counts; means use total byte and packet counters. Seattle's chart percentages are time-averaged sampled proportions.

Workstream 2 / ConCap-AuthStorm-2026

Variation begins with the attack procedure

ConCap runs live authentication attacks while varying tool options, concurrency, credentials and network conditions. Each accepted scenario retains its configuration and packet capture.

Execution variation

Six tools cover different attack implementations. Credential profiles and password placement can change progress through an attack and its termination.

Channel variation

Bandwidth, delay, jitter, loss, duplication and corruption alter the transport conditions. Reruns preserve the procedure, but scheduling can change the resulting packets.

The work connecting both projects

Dataset audits improved the extractor

Bulk-transfer measurements exposed a timing and rate-unit defect. The correction prompted a complete, audited regeneration of the accepted corpus.

01 / Diagnose

Find the measurement defect

Millisecond truncation and incorrect rate units distorted bulk-transfer features.

02 / Correct

Keep microsecond precision

Integer microsecond timing fixes rate calculations while preserving the feature schema and packet-byte accounting.

03 / Verify

Reconcile the regenerated data

All extracted packet counts reconcile. The audited revision has no non-bulk feature changes and no nonfinite rates.

What the regeneration checks established

All 1,172 scenarios and 1,019,250 flow records were regenerated. The 18,906,131 extracted packets reconcile; 463 excluded frames match documented intentional-corruption exceptions. No bulk-membership changes occurred in this corpus.

Original captures and executed configuration hashes match the frozen inventory. All 69,520 legacy annotation rows were preserved and linked. The crosswalk leaves 46 rows in duplicate-identity groups explicitly ambiguous rather than inventing row-order correspondence.

The release pins the October extractor and its five-thread settings. It does not silently adopt the later November semantics. Future extractor upgrades require a separately audited revision.

Use and interpretation

A resource for testing generalization

Primary use

Evaluate a fixed detector

Keep the detector and its preprocessing fixed, then test on unseen attack variants. Retained captures allow re-extraction when a model needs its original feature pipeline.

Optional internal protocol

Use the predefined split

The test partition holds out Medusa or a configured delay of at least 100 ms. Related source scenarios stay together.

Development: 1,007 scenarios / 858,081 flows
Test: 165 scenarios / 161,169 flows

Parquet features, separate metadata, scenario catalogs and provenance support inspection and reuse. Identifiers and labels are excluded from the model input list.

Compatibility

Mappings match local RustiFlow CIC-, CIDDS- and NFStream-inspired exporters. External extractor equivalence still needs validation, including flow direction and segmentation.

Coverage

Tools and services are unevenly represented. The test partition has no IMAP or POP3 scenarios.

Interpretation

Tool and channel effects overlap. Individual flows are not independent experiments, and the collection does not establish production representativeness.

Evidence

Feature-distribution differences are documented. Detector generalization remains untested.

Records, repeats and feature semantics

The collection contains 992,524 distinct complete feature vectors within 1,019,250 flow records. Repeated vectors can reflect ordinary control traffic and remain in the release because they occurred in captured executions.

Labels describe scenario outcomes. A successful scenario does not imply that every flow contains a successful login. CIDDS-001 uses unidirectional records; AuthStorm currently uses bidirectional flows, so matching field names alone does not establish compatibility.
